## 一、从 Obsidian 迁移

### 1.1 迁移前的准备

迁移过程会**读取**你的 Obsidian 仓库、**写入** Neo MD 仓库，不会修改源目录。但仍建议按顺序做三件事：

1. **完整备份 Obsidian 仓库**。直接复制整个文件夹到别处即可（保险起见，这是唯一不可省的一步）。
2. **关闭 Obsidian**。避免导入过程中文件被占用或内容正在写入。
3. **确认 Neo MD 仓库位置**。迁移是写进当前打开的 Neo MD 仓库；想单独放一个仓库，先在 Neo MD 里切换或新建一个。

### 1.2 操作步骤

1. 打开 **设置**（`Ctrl+,`）。
2. 进入 **导入** 分区。
3. 点击 **选择 Obsidian 仓库目录**，选中你的 Obsidian 仓库根目录（就是包含 `.obsidian/` 的那个文件夹）。
4. 选择 **目标文件夹**：留空表示导入到 Neo MD 仓库根目录；填 `Obsidian迁移` 则全部放进该子文件夹，方便你之后慢慢整理。
5. 按需调整下方选项（见 [1.3](#13-选项说明)，**首次迁移建议保持默认**）。
6. 点击 **开始导入**，等待进度完成。
7. 查看导入报告（见 [1.4](#14-导入报告解读)）。

### 1.3 选项说明

选项与代码中的 `ObsidianImportOptions` 一一对应。

| 选项 | 默认 | 作用 | 什么时候改 |
| --- | --- | --- | --- |
| **目标文件夹** | 空（根目录） | 导入到 Neo MD 仓库的哪个文件夹 | 想和已有笔记分开时填一个子目录名 |
| **保留文件时间** | 开启 | 保留源文件的修改 / 创建时间 | **强烈建议保持开启**。关闭后所有笔记的时间线会被压平成导入当天，历史版本排序与「最近打开」全部失真，且**不可逆** |
| **转换 Obsidian 专用语法** | 开启 | 下面是各项转换的总开关 | 只想原样搬过来（之后自己处理）时才关 |
| **转换嵌入资源** | 开启 | `![[image.png]]` → 相对路径图片引用 | 笔记里有截图时保持开启，否则图片会显示不出来 |
| **转换注释** | 开启 | `%%注释%%` → HTML 注释 | 保持开启。关闭后注释会**当成正文显示**出来 |
| **转换 Callout** | 开启 | `> [!note]` → 引用块 + 粗体标题 | 重度使用 callout 时开启，保留视觉层次 |
| **转换高亮** | 开启 | `==高亮==` → `<mark>` | 保持开启，否则 `==` 会原样显示 |
| **规范任务列表** | 开启 | `- [ ]` → 标准 GFM 任务列表 | 保持开启，保证勾选框可点击 |
| **规范硬换行** | 开启 | 行尾空格 / 单个换行 → CommonMark 两空格换行 | 保持开启。关闭后段落可能被合并成一大段，或换行位置与原文不同 |
| **跳过配置目录** | 始终开启 | 忽略 `.obsidian/`、`.trash/` 等 | 不可关闭（导入这些目录没有意义） |
| **同名文件处理** | `rename` | 冲突策略：`rename` 重命名 / `overwrite` 覆盖 / `skip` 跳过 | 反复迁移同一仓库时用 `skip`；完全替换某批笔记时用 `overwrite`（**会丢数据，慎用**） |

<!-- 截图占位：选项逐项说明
![选项说明](images/user-guide/obsidian-04-option-detail.png)
-->

**典型选择建议**：

- **第一次迁移**：全部默认（`rename`）——最安全，不会覆盖任何东西。
- **反复试跑调参**：把「同名文件处理」改成 `skip`，避免产生一堆 `xxx-1.md`、`xxx-2.md`。
- **只想搬正文、不要花哨格式**：关掉「转换 Callout」「转换高亮」，让它们以原文形式保留。

### 1.4 导入报告解读

导入结束后会给出汇总与逐文件明细，对应 `ObsidianImportReport`。

**汇总区**

| 字段 | 含义 |
| --- | --- |
| `vaultName` | 仓库名称 |
| `total` | 扫描到的文件总数 |
| `imported` | 原样导入（未触发任何转换） |
| `converted` | 转换后导入（至少应用了一项语法转换） |
| `skipped` | 按策略跳过（同名 `skip`，或位于被忽略目录） |
| `failed` | 失败，逐文件明细里有具体原因 |
| `ignoredPaths` | 被跳过的配置目录 / 文件说明 |
| `durationMs` | 耗时（毫秒） |

**逐文件明细**

每条记录包含源路径、目标路径、大小、源修改 / 创建时间、状态、实际应用的转换列表，失败时附错误原因。

**状态含义**

| 状态 | 含义 | 需要你做什么 |
| --- | --- | --- |
| `imported` | 原样导入 | 无 |
| `converted` | 转换后导入 | 建议抽查几篇，确认转换效果符合预期 |
| `skipped` | 按策略跳过 | 确认是否你主动选择跳过；若不想跳过，换 `rename` 策略重试 |
| `conflict` | 检测到同名冲突 | 按报告里的路径处理后重试 |
| `failed` | 失败 | 看 `error` 字段；常见是编码异常或磁盘空间不足 |

**读报告的三个要点**：

1. **先看 `failed`**。只要 `failed = 0`，即使有 `skipped` 也说明导入流程没出错。
2. **再看 `converted` 里的转换明细**。如果某篇的关键笔记显示转换了 `hardBreaks`，建议打开对照原文确认段落没被合并。
3. **最后确认 `skipped`**。如果跳过的数量明显超出预期，通常是「同名文件处理」选了 `skip`，或目标文件夹里已有同名文件。

### 1.5 迁移后的检查清单

- [ ] **随便打开 3–5 篇**：一篇纯文字、一篇带图片、一篇有 callout、一篇有任务列表、一篇有代码块。
- [ ] **图片能显示**：若裂图，检查原仓库的图片是否在笔记同目录或 `attachments/` 下，并且该目录也被一起导入。
- [ ] **换行位置正确**：段落没有被合并成一大段，也没有在不该断的地方断开。
- [ ] **任务列表可勾选**：`- [ ]` 显示为可点击的勾选框，而不是纯文本。
- [ ] **注释没有跑出来**：`%%...%%` 的内容不应该出现在正文里。
- [ ] **创建时间合理**：文件列表按时间排序时，旧笔记没有全部挤在导入当天。
- [ ] **双向链接还能用**：`[[笔记名]]` 能跳转。若目标笔记也一起导入了，链接应该自动生效。
- [ ] **搜索能命中中文**：用 `Ctrl+Shift+F` 搜一个中文词，确认索引已建好。

### 1.6 迁移常见问题

**Q：图片显示不出来（裂图）**
A：多数是三种原因——① 图片放在 Obsidian 仓库外的绝对路径；② 用了 Obsidian 的私有嵌入语法且关闭了「转换嵌入资源」；③ 图片所在目录被当作配置目录跳过了。确认图片确实在仓库内、开启嵌入转换、用 `rename` 策略重试。

**Q：段落被合并成一大段 / 换行没了**
A：Obsidian 和 CommonMark 对换行的处理不同。确认「规范硬换行」开启后重新导入；已导入的笔记可以打开源码模式手工修，或删掉该篇后重导。

**Q：`> [!warning]` 这种 callout 显示成普通文字**
A：开启「转换 Callout」。注意转换结果是「引用块 + 粗体标题」的等价写法，并非 Obsidian 那种带图标的样式——这是 Markdown 标准下的通用做法。

**Q：`%%这不是正文%%` 出现在文章里了**
A：开启「转换注释」，它会被转成 HTML 注释，渲染时不显示。

**Q：导入后所有笔记时间都一样**
A：迁移时关闭了「保留文件时间」。这个选项**不可事后补救**（源时间信息已经丢失），只能从 Obsidian 源目录重新导入一次。

**Q：出现一堆 `笔记名-1.md`、`笔记名-2.md`**
A：同名文件策略用了 `rename`。这是安全默认值。想避免重复，把策略改成 `skip`，或先清理目标文件夹再导入。

**Q：`.obsidian` 也被导入了吗**
A：不会。配置目录始终跳过，报告中会在 `ignoredPaths` 里列出。

**Q：可以同时迁移多个 Obsidian 仓库吗**
A：可以。用不同的目标文件夹分多次导入，Neo MD 会把它们合并到同一个仓库中。

## 二、使用 AI 知识库

### 2.1 开启知识库

1. 打开 **设置**（`Ctrl+,`）→ **知识库**。
2. 打开 **启用知识库** 开关。
3. 选择一种 **切片颗粒度**（先保持默认的「段落」，见 2.2）。
4. 等待首次索引建立完成（状态会显示进度；仓库越大越久，之后开启自动索引就只会增量更新）。

关闭开关后，**检索与服务端调用全部返回空**，不会消耗积分，也不会有任何请求发出。

<!-- 截图占位：知识库设置总览
![知识库设置](images/user-guide/knowledge-01-settings.png)
-->

> **前提**：知识库让 AI 回答你的问题，本身不是 AI。仍需要在「设置 → AI」里配置好供应商与模型（自带 Key 或使用平台积分）。

### 2.2 五种颗粒度分别适合什么场景

这是影响效果最直接的设置。颗粒度决定了「一段被送去 AI 的上下文有多长」。

| 颗粒度 | 切分依据 | 一段大概多长 | 最适合 | 不适合 |
| --- | --- | --- | --- | --- |
| `heading` | 按 H1–H6 标题切 | 一个章节 | **长文、结构化笔记**（技术文档、项目方案、读书笔记）。因为保留了完整章节上下文，AI 不容易断章取义 | 标题层级混乱、全文没有标题的笔记 |
| `paragraph` | 按段落切（空行分隔） | 一到几段 | **默认推荐，绝大多数场景**。检索精度与上下文长度兼顾，是「不知道选什么」时的正确答案 | 极短笔记（一段就是全文，退化成 doc） |
| `sentence` | 按句切（`。！？；` 与换行） | 一句话 | **精确问答与原文定位**。例如「XX 的定义是什么」「某条规则怎么写的」，希望 AI 引用原句 | 需要跨句推理、总结类问题（上下文太碎，AI 看不到全貌） |
| `block` | 固定字符数滑动窗口 | 由 `chunkSize` 决定 | **无结构长文**：连续日记、会议速记、剪藏网页、大段流水账。靠 `chunkOverlap` 避免句子被腰斩 | 结构清晰、标题规整的笔记（用 `heading` 更好） |
| `doc` | 整篇文档一个切片 | 一整篇 | **摘要 / 概括类问答**：「帮我总结这几篇」「这篇讲了什么」。粒度最粗但上下文最完整 | 检索精度要求高的场景（一篇长文塞进去会超 `maxContextChunks`，且容易答偏） |

**怎么选，一句话版**：

- 不确定 → **`paragraph`**（默认）。
- 笔记有大纲、章节分明 → **`heading`**。
- 要「原话是怎么写的」 → **`sentence`**。
- 日记 / 流水账 / 剪藏 → **`block`**。
- 让 AI 做概括 → **`doc`**。

> 同一份笔记可以随时换颗粒度，重建索引即可，源文件不受任何影响。可以拿同一个问题在 `paragraph` 与 `heading` 下各问一次，直观感受差异。

### 2.3 `topK` 与 `minScore` 怎么调

这两个参数一起决定「送多少片段给 AI」。

| 参数 | 范围 | 含义 | 调大的后果 | 调小的后果 |
| --- | --- | --- | --- | --- |
| `topK` | 1–30 | 单次最多返回多少个片段 | 召回更全，但上下文变长 → token 消耗上升、AI 容易被无关内容干扰 | 上下文更聚焦，但可能漏掉关键片段 |
| `minScore` | 0–1 | 相关性阈值，低于此分数的片段直接丢弃 | 只保留高置信片段 → 精准但可能「什么都没检索到」 | 更宽松，召回多但噪声大 |

**推荐调法（顺序很重要）**：

1. **先定 `minScore`**，再调 `topK`。
   - 先把 `minScore` 设低（如 `0.2`），`topK` 设大（如 `10`），问一个你确定答案存在的问题，观察返回片段的相关性。
   - 逐步提高 `minScore`，直到「明显不相关」的片段不再出现。
2. **再压 `topK`**，在保证召回的前提下尽量小。
   - 从大到小试，直到再减一就漏掉关键信息为止。
3. **最后用真实问题验收**，而不是用你已知答案的问题——后者容易自欺欺人。

**起步值建议**：

| 场景 | `topK` | `minScore` |
| --- | --- | --- |
| 笔记量大、问题具体 | 5 | 0.5 ~ 0.6 |
| 笔记量小、问题宽泛（「总结下」） | 10 ~ 15 | 0.3 |
| 只想让 AI 引用原文原句 | 3 ~ 5 | 0.6 ~ 0.7 |
| 试探「库里到底有没有相关内容」 | 20 | 0.2 |

> **一个常见误区**：`topK` 越大不代表回答越好。如果检索质量差，塞进更多片段只会让 AI 更困惑，还多花钱。宁可用更好的颗粒度 + 更严格的阈值，也不要靠堆数量。

### 2.4 其余参数

| 参数 | 范围 | 说明 | 建议 |
| --- | --- | --- | --- |
| `searchMode` | `keyword` / `hybrid` / `vector` | 检索模式：纯关键词 / 混合 / 向量 | 中文笔记先用 `hybrid`；专业术语多、希望精确匹配时用 `keyword` |
| `chunkSize` | 200–4000 | **仅 `block` 粒度生效**：每个切片的字符数 | 800–1200 是较好的平衡点 |
| `chunkOverlap` | 0–500 | **仅 `block` 粒度生效**：相邻切片的重叠字符数 | 取 `chunkSize` 的 10%–20%，防句子被腰斩 |
| `maxDocChars` | — | 单文档最多纳入多少字符，超出截断 | 防止超大文件拖垮索引；有超长日志文件时调低 |
| `autoIndex` | 开 / 关 | 文件变动后自动增量重建该文档的切片 | **建议开启**。关闭后需要手动重建，新写的笔记搜不到 |
| `maxContextChunks` | — | 注入 AI 上下文时最多带多少片段 | 一般等于或略小于 `topK`；直接影响 token 消耗 |
| `keepMarkdown` | 开 / 关 | 片段保留 Markdown 原样（关闭则转纯文本） | 开启，AI 更容易理解结构（表格、列表） |
| `includeFrontmatter` | 开 / 关 | 是否把 frontmatter 元数据纳入切片 | 用 frontmatter 存标签 / 日期 / 状态时开启 |

### 2.5 控制纳入范围

不想让某些内容进入知识库，用两项排除设置：

| 设置 | 写法 | 例子 |
| --- | --- | --- |
| `excludeFolders` | 目录前缀，每行一个 | `日记/`、`归档/`、`收件箱/私有/` |
| `excludeTags` | 标签名，每行一个 | `private`、`secret`、`草稿` |

命中任一条件的笔记**不会进入知识库**，也就不会被 AI 读到。适合：

- 私人日记、财务记录不参与问答；
- 归档区的旧项目不污染检索结果；
- 未完成的草稿不进入正式知识库。

> 排除是**索引层面**的过滤，不改动、不删除你的文件。取消排除后重建索引即可恢复。

### 2.6 隐私：索引不出本机

这是知识库最重要的设计约定：

- **切片、建索引、检索全部在你的设备上完成**，笔记正文不上传到服务器；
- 服务端只做一件事——把「你这次问的问题 + 本地检索出的几个片段」转发给 AI 供应商，**用完即弃，不落库、不写盘**；
- 服务端日志不记录片段正文（只有请求 ID、耗时、token 用量）；
- 云端同步的设置里只有参数（颗粒度、`topK` 等），**没有任何笔记内容**。

如果你连「片段经过服务器转发」也不想接受，开启 PC 端的**数据私有化模式**（设置 → 服务器 → 数据私有化）：客户端完全不连服务器，知识库退化为纯本地检索，AI 问答不可用。

技术细节见 [部署指南 · 知识库 API](./DEPLOYMENT.md#十四知识库-api)。

### 2.7 知识库常见问题

**Q：开了知识库，AI 还是说「没有找到相关内容」**
A：按顺序排查——① 索引是否建完（看进度状态）；② `minScore` 是否设太高（降到 0.2 试）；③ 目标笔记是否被 `excludeFolders` / `excludeTags` 排除；④ 笔记是否真的包含关键词（换个说法再问）；⑤ `searchMode` 试试 `keyword`。

**Q：回答很啰嗦、带了很多无关内容**
A：`topK` 太大或 `minScore` 太低。按 2.3 的顺序收紧：先提 `minScore`，再压 `topK`。

**Q：新写的笔记立刻搜不到**
A：确认 `autoIndex` 开启；刚保存的文档索引是异步的，等几秒或切一次标签页触发。

**Q：同一个问题两次回答差异很大**
A：这是 AI 采样本身的随机性。想稳定复现，固定 `topK` / `minScore` 与模型，并避免用 `doc` 粒度（上下文越长，模型发挥空间越大）。

**Q：知识库会把我所有笔记都发给 AI 吗**
A：不会。只发送本次检索命中的、数量不超过 `topK` / `maxContextChunks` 的片段。

**Q：换电脑后要重新建索引吗**
A：索引可随仓库同步；若目标设备没有索引，会自动重建一次。重建期间检索不全属于正常现象。

**Q：知识库支持 PDF / 图片吗**
A：知识库面向仓库内的 Markdown 笔记。其他格式需先转成 `.md` 才能被索引。

## 三、使用思维导图与流程图

### 3.1 新建一张图

图是仓库内的**普通文件**，和 `.md` 笔记平级：

| 类型 | 扩展名 | 用途 |
| --- | --- | --- |
| 思维导图 | `.mind` | 发散、梳理结构、拆解问题 |
| 流程图 | `.flow` | 步骤、判断分支、状态流转 |

新建后在侧栏双击即可打开图编辑器；也可右键菜单重命名、移动、删除，行为与笔记一致。

> 图文件保存为 **JSON**，所以它天然支持：随仓库被 S3 同步到各端、纳入版本历史后回滚、用文本 diff 审阅结构变化。这让图和你其它笔记享受完全一样的管理方式。

### 3.2 思维导图

**布局方向**有 4 种，对应 `mindmapLayout`：

| 布局 | 效果 | 适合 |
| --- | --- | --- |
| `right` | 从根节点向右展开 | 最常见的目录 / 大纲结构 |
| `left` | 向左展开 | 左右对照、与右侧面板配合时更顺 |
| `both` | 向两侧对称展开 | 中心主题 + 双向外延的分支梳理 |
| `down` | 向下展开 | 层级深、层级名称长（避免文字挤在一起） |

**操作要点**：

- 选中节点按 Tab 建**子节点**、按 Enter 建**同级节点**（分支关系随布局自动重排，无需手工拖位置）。
- 节点可**折叠**（`collapsed`），收起一大片分支只看主干。
- 每个节点可设置形状、填充 / 描边 / 文字颜色、字号、加粗斜体、图标 emoji、备注。
- 备注（`note`）不出现在节点框里，只在悬停与导出时可用——适合放「这句话的出处」「待补充」。

### 3.3 流程图

**10 种节点形状**（对齐常用图形集）：

| 形状 | 惯用含义 |
| --- | --- |
| 矩形 `rect` | 处理 / 步骤 |
| 圆角矩形 `roundRect` | 起止节点、可复用的子流程 |
| 椭圆 `ellipse` | 开始 / 结束 |
| 菱形 `diamond` | 判断 / 分支 |
| 平行四边形 `parallelogram` | 输入 / 输出 |
| 六边形 `hexagon` | 准备 / 初始化 |
| 圆柱 `cylinder` | 数据库 / 存储 |
| 文档 `document` | 文档 / 报表产物 |
| 圆形 `circle` | 连接点、汇合 |
| 纯文本 `text` | 注释、说明文字 |

**连线**：

- **锚点**（`DiagramPort`）：上 / 右 / 下 / 左 / 中心 / 自动。选「自动」时会挑一个最短路径的边，手动指定则固定连接位置。
- **箭头**（`DiagramArrow`）：无 / 箭头 / 三角 / 圆点 / 菱形，起点和终点**分别**设置。
- **线型**（`DiagramLineStyle`）：实线 / 虚线 / 点线。虚线常用于异步或弱依赖关系。
- **折线**：拖动连线可增加拐点（`waypoints`），自动走正交路径，适合工程风格流程图。
- **曲线**：切换为曲线（`curved`）让走向更柔和，适合环形、交叉较多的图。
- **标签**：连线上可写文字，常用于标「是 / 否」「成功 / 失败」。

### 3.4 画布操作

| 操作 | 方式 |
| --- | --- |
| 平移画布 | 拖动空白处；或使用右下角的缩放 / 导航控件 |
| 缩放 | `Ctrl + 滚轮`，或使用缩放控件 |
| 框选多个节点 | 在空白处拖出选框 |
| 移动节点 | 拖动节点；多选后一起拖动 |
| 调整尺寸 | 拖节点边角的控制点 |
| 吸附网格 | 开启「吸附」后节点与网格对齐，图更整齐 |

**画布设置**（对应 `DiagramSettings` 与画布配置）：

| 设置 | 字段 | 选项 / 范围 | 说明 |

| 字段 | 含义 |
| --- | --- |
| `mindmapLayout` | 新建思维导图的默认布局方向 |
| `grid` | 新建图的默认网格样式 |
| `snapToGrid` | 是否默认吸附网格 |
| `gridSize` | 网格大小 |
| `nodeFill` | 默认节点填充色 |
| `nodeStroke` | 默认节点描边色 |
| `edgeStroke` | 默认连线色 |
| `autoSave` | 是否自动保存 |
| `showMinimap` | 是否显示小地图 |

| 操作 | 方式 |
| --- | --- |

### 3.6 导出

导出以节点的**世界坐标**（`x/y/w/h`）为准，**缩放与平移不影响导出结果**——所以你在画布上怎么缩放预览都不影响出图。

导出前建议做三件事：

1. 关掉网格与「显示网格」，避免背景网格被一起导出；
2. 检查是否有节点折叠着——折叠的分支通常不会被导出，想展示就用「全部展开」；
3. 确认备注不需要出现在图里（备注默认不参与渲染）。

> 可选的导出格式以客户端「导出」菜单中的实际选项为准。

### 3.7 保存、同步与版本

- **自动保存**：`DiagramSettings.autoSave` 开启后编辑即自动保存（建议开启）。
- **手动保存**：`Ctrl + S`。
- **同步**：图文件与其他笔记走同一套 S3 同步，无需额外配置。
- **版本历史**：每次保存留痕，可对比与回滚——画废了不怕，直接回退。
- **冲突**：多端同时改同一张图时，与笔记一样走冲突处理（另存为或采用远端版本）。

### 3.8 图相关常见问题

**Q：图能嵌进笔记里吗**
A：图是独立文件，可在笔记中用链接引用（如 `[[我的导图.mind]]`）。具体嵌入渲染以客户端版本为准。

**Q：导入 Obsidian 时，Obsidian 的 Canvas 文件会一起导入吗**
A：Obsidian Canvas 是另一种格式（`.canvas`），与 Neo MD 的 `.mind` / `.flow` 不同。导入仅处理 Markdown 笔记与嵌入资源；Canvas 文件不会被自动转换。

**Q：节点太多，编辑卡**
A：关掉小地图与网格，并把 `autoSave` 的触发间隔放宽（若客户端提供该设置）。超大图建议拆成多张。

**Q：导出的图和屏幕上不一样**
A：先确认是否开着网格（会被导出），再确认是否有折叠节点。导出走世界坐标，缩放不影响结果，因此差异通常来自这两项。

**Q：多人协作同一张图会冲突吗**
A：会。图与笔记一样按 `updatedAt` 与三方合并处理，冲突时按弹窗提示选择保留本地或采用远端。
