# 自建服务端与 PC 端「自定义服务器」

本文说明如何把自己部署的 Neo MD 服务端接到 PC 客户端上，以及切换后**哪些能力走你的服务器、哪些不走**。

前置：服务端已按 [DEPLOYMENT.md](./DEPLOYMENT.md) 部署完成，且 `https://你的域名/api/health` 返回 `ok: true`。

---

## 一、能力概览（1.0.2 起）

1.0.2 起，PC 客户端把服务端地址从「编译期常量」改为「运行时可配置项」：

| 维度 | 1.0.1 及以前 | 1.0.2 起 |
| --- | --- | --- |
| API 基地址 | 构建时写死（`VITE_API_BASE` 或默认官方域名） | 用户可在「设置 → 服务器」运行时填写 |
| 切换服务端 | 需要重新打包客户端 | 改一个输入框，保存即生效 |
| 适用场景 | 只能用官方实例 | 企业内网部署、完全数据私有化 |
| 多环境并存 | 不支持 | 同一台电脑可随时在官方 / 自建之间切换 |

---

## 二、PC 端操作步骤

### 2.1 打开设置

启动 Neo MD 桌面客户端 → 左下角头像 / 用户名 → **设置**（也可用命令面板 `Ctrl+P` 搜索「设置」）。

### 2.2 进入「服务器」分区

在设置弹窗左侧找到 **服务器**（`ServerSettingsSection`）。该分区包含：

| 控件 | 作用 |
| --- | --- |
| 服务器地址 | 填写自建服务端根地址 |
| 测试连接 | 请求 `/api/health`，给出成功 / 失败原因 |
| 保存 | 持久化到本机并立即切换所有 API 请求目标 |
| 恢复默认 | 清空自定义地址，回退到官方服务 |

### 2.3 填写地址

**填根地址，不要带 `/api` 后缀**，表格中 `✅` 为正确写法：

| 场景 | 填写示例 | 说明 |
| --- | --- | --- |
| 公网 HTTPS | `https://md.example.com` | ✅ 推荐，与 Nginx 终止 TLS 的入口一致 |
| 内网 IP + 端口 | `http://192.168.1.10:3200` | ✅ 适合内网机器直连后端（需 `HOST` 不是 `127.0.0.1`） |
| 带路径前缀 | `https://example.com/neomd` | ⚠️ 仅当 Nginx 做了子路径反代且后端支持时可用 |
| 拼上接口路径 | `https://md.example.com/api` | ❌ 会拼成 `/api/api/...`，必然 404 |
| 结尾斜杠 | `https://md.example.com/` | ✅ 会自动去重，但不建议依赖 |

保存后，客户端内部会把所有 `/api/...` 请求解析为该根地址 + 路径，例如：

```text
设置：https://md.example.com
请求：/api/auth/login   →   https://md.example.com/api/auth/login
```

### 2.4 测试连接

点击「测试连接」，客户端会请求 `<你的地址>/api/health`。可能的结果：

| 返回 | 含义与处理 |
| --- | --- |
| `ok: true` + `db: true` | 正常，可以登录 |
| `ok: true` + `db: false` | 服务端在跑但连不上 MySQL，回去查 `DB_*` 配置 |
| 连接超时 | 地址不可达：检查端口、防火墙、安全组、域名解析 |
| TLS / 证书错误 | 证书无效或自签名，见 [第四节](#四常见问题与排错) |
| 404 | 地址填错（多了 `/api`、少了路径前缀）或 Nginx 未反代到后端 |

## 三、切换后的能力边界

### 3.1 走你的服务端（数据平面）

| 能力 | 说明 |
| --- | --- |
| 注册 / 登录 / 刷新令牌 | 账号体系完全在你自己的 MySQL 中 |
| 个人资料与头像 | 头像文件写入你的对象存储 |
| 云端设置同步 | 用户设置（含加密后的密钥字段）存在你的库 |
| 积分与兑换码 | 平台积分体系由你的库与后台驱动 |
| 分享链接 `/s/<token>` | 数据与访问控制都在你的服务端 |
| 静态发布 `/p/<slug>` | 渲染产物写入你的对象存储 |
| 文件上传 / 备份 | 走你的对象存储 |
| AI 代理（平台积分模式） | 由你在管理后台配置的供应商密钥与优先级队列决定 |
| 管理后台 `/admin` | 你的实例独立的后台与审计日志 |
| 客户端安装包分发 | `/api/download/:file` 指向你的对象存储 |

### 3.2 不走你的服务端

| 能力 | 实际来源 |
| --- | --- |
| **插件市场（应用商店）** | **官方统一服务，不支持私有化** |
| 笔记正文与本地仓库 | 纯本地文件（本机文件夹），与任何服务端无关 |
| S3 同步（自带 Key 模式） | 直连用户自己的对象存储，不经服务端 |
| 自带 Key 的 AI 调用 | 客户端直连第三方供应商，不经服务端 |
| 客户端程序本身的更新检查 | 官方分发渠道 |

> 换句话说：**笔记数据本来就私有；自建服务端解决的是「账号与协作元数据不要经过第三方」。**

## 四、常见问题与排错

### 4.1 保存后登录仍失败，控制台报 CORS

自建站点的域名必须加入服务端的 `CORS_ORIGINS`：

```ini
CORS_ORIGINS=https://md.example.com
```

改完重启服务端。注意服务端已内建放行 `localhost` / `127.0.0.1` 的任意端口以及 `neomd://`、`capacitor://` 等自定义协议，因此**桌面客户端**本身不受 CORS 限制，但**网页版**直接访问自建域名时会受限。

### 4.2 测试连接报证书错误

Electron 对证书校验较为严格。三种处理：

1. **推荐**：给自建域名申请正式证书（Let's Encrypt 免费，宝塔一键申请）；
2. 用内网 IP + `http://` 访问（仅限内网，且不要跨公网传输凭据）；
3. 完全离线环境：把自建 CA 根证书导入 Windows「受信任的根证书颁发机构」，然后重启客户端。

### 4.3 内网可用、外网不可用

- 确认 `PUBLIC_BASE_URL` 与客户端填写的地址一致，否则分享链接会指向一个外网打不开的地址；
- 确认 `HOST`：默认 `127.0.0.1` 只监听回环，Nginx 同机反代没问题；若要客户端**直连端口**，需要改成 `0.0.0.0` 并用防火墙限制来源；
- 确认云服务器安全组放行 443（80 仅用于跳转与证书校验）。

### 4.4 切换后旧账号登不上

自建实例的账号库是全新的。官方实例的账号不会迁移过来，需要在你的实例上重新注册，或用 `.env` 里的 `ADMIN_*` 账号登录后创建用户。

### 4.5 想同时保留官方与自建

「设置 → 服务器」是**按设备保存**的配置。可以在不同设备上分别指向不同实例；同一台设备切换时，本地笔记不受影响（笔记在本机文件夹），但云端设置与分享等元数据会跟随所连服务端。

### 4.6 如何彻底恢复官方服务

设置 → 服务器 → **恢复默认**，或清空地址后保存。客户端会回退到默认官方地址。

## 五、插件市场的边界

> **插件市场（应用商店）始终使用官方统一服务，不支持私有化部署。**

具体含义：

| 行为 | 是否受影响于自定义服务器 |
| --- | --- |
| 浏览插件市场列表 | ❌ 不受影响，始终拉官方数据 |
| 下载 / 安装市场插件 | ❌ 不受影响 |
| 发布自己的插件到市场 | ❌ 不受影响，走官方账号体系 |
| 查看自己的安装量与获赞 | ❌ 不受影响 |
| **内置 24 款插件的启用 / 关闭** | ✅ 完全本地，与任何服务端无关 |
| **本地导入 `.js` 插件脚本** | ✅ 完全本地，无需登录 |

如果你的合规要求是「任何出网请求都不得触达第三方」，那么插件市场相关入口需要在网络层做阻断 —— 这是刻意的产品边界，不提供私有化商店。

## 六、附录：实现约定（面向贡献者）

| 关注点 | 位置 |
| --- | --- |
| 设置界面「服务器」分区 | `apps/web/src/components/panels/ServerSettingsSection.vue` |
| 地址解析与请求拼接 | `apps/web/src/api/client.ts` → `resolveApiUrl()` |
| 服务端健康检查 | `services/api/src/routes/health.js` → `GET /api/health` |
| 跨域放行规则 | `services/api/src/server.js` → `@fastify/cors` 的 `origin` 回调 |
| 环境常量与默认站点 | `apps/web/src/env.ts`（`SITE_URL` / `API_BASE`） |

**地址解析优先级**（1.0.2 目标行为，自高到低）：

1. 用户在本机「设置 → 服务器」保存的运行时地址；
2. 构建期注入的 `VITE_API_BASE`；
3. 网页端（同源 http/https）→ 相对路径 `/api/...`；
4. 桌面端 / Android 自定义协议 → 默认官方地址 `https://md.zhengl.vip`。

这样设计的原因：桌面端页面运行在 `neomd://neomd/app` 或 `capacitor://localhost`，直接发相对路径请求会命中本地静态协议并返回 `index.html`（表现为「请求失败 (200)」），所以必须有一个绝对基地址兜底。
